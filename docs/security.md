# Безопасность API

## Rate limiting

API ограничивает запросы по IP: отдельный лимит применяется к auth-маршрутам и к остальным API-запросам. При превышении сервер возвращает `429 rate_limited` и `Retry-After`.

В production счётчик должен быть перенесён в Redis, чтобы лимит был общим для всех экземпляров API.

## Практика магазина

- не помещайте secret API key в browser/frontend;
- используйте новый `Idempotency-Key` для каждой бизнес-операции;
- проверяйте HMAC webhook;
- включите 2FA для всех сотрудников;
- ограничьте ключ по IP в production;
- отзывайте ключ при подозрении на утечку.
