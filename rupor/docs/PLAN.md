# РУПОР — подробный план реализации биржи рекламы

> **Рупор** *(мегафон)* — биржа рекламы RU-сегмента, где владельцы каналов,
> чатов и ботов **Telegram и VK** размещают свои площадки с публичными ценами,
> а рекламодатель покупает размещения с эскроу-защитой средств.
>
> Слоган: «Реклама в Telegram и VK — напрямую от владельцев».

---

## 1. Концепция и позиционирование

| | |
|---|---|
| **Проблема** | Рынок TG/VK-рекламы живёт в чатах-барахолках и у брокеров: цены непрозрачны, нет гарантий, оплата «на доверии», статистика рисуется. |
| **Решение** | Каталог площадок с открытым прайсом, фильтрами и отзывами + внутренний баланс с эскроу: деньги переводятся владельцу только после подтверждения размещения рекламодателем. |
| **ЦА** | 1) Владельцы каналов/чатов/ботов (заработок). 2) Малые рекламодатели: арбитражники, инфопродукты, крипто-проекты, локальный бизнес. |
| **Отстройка** | Эскроу + отзывы только от реальных заказов + фокус на 2 платформы (Telegram, VK) для RU-аудитории. |
| **Модель монетизации** | Комиссия 10% с завершённых заказов (настраивается), далее: платное продвижение площадок, платная верификация, подписка PRO. |

### Альтернативные названия (если «Рупор» занят доменом)
«Катапульта», «Эфир», «Аудитория», «МедiаБазар», «Прямой Эфир». Название
вынесено в конфиг (`APP_NAME`) — переименование в 1 строку.

## 2. Роли и сценарии

**Владелец площадки**
1. Регистрация → добавление площадки (платформа, тип, ссылка, категория, охват, ER, описание).
2. Публичный прайс: пост 24/48/72 ч, репост, нативный пост.
3. Модерация → публикация в каталоге.
4. Приём заказов: просмотр материалов → принять / отклонить (авто-возврат).
5. Публикация рекламы → кнопка «Размещено».
6. Получение выплаты на внутренний баланс после подтверждения покупателем.

**Рекламодатель**
1. Пополнение баланса (CryptoBot / xRocket / ЮMoney).
2. Поиск: фильтры платформа/тип/категория/цена/охват/ER + поиск + сортировки.
3. Бронирование размещения (эскроу-удержание), передача материалов и контакта.
4. Контроль: подтвердить выполнение / открыть спор (арбитраж) / отменить новый заказ.
5. Отзыв с оценкой после завершённого заказа.

**Администратор**
1. Модерация площадок (одобрить/отклонить с причиной), галочка «подтверждена».
2. Арбитраж споров: возврат покупателю или выплата владельцу.
3. Ручное подтверждение пополнений, корректировка балансов, бан пользователей.
4. Метрики: пользователи, площадки, заказы, GMV, доход с комиссии.

## 3. Архитектура (текущая — MVP)

```
┌────────────────────────────────────────────────────────┐
│  FastAPI (синхронные обработчики + Jinja2 SSR)         │
│  /app/main.py — сборка приложения                      │
│  /app/web/public.py    — главная, каталог, карточка    │
│  /app/web/account.py   — ЛК, площадки, баланс, заказы  │
│  /app/web/admin.py     — модерация, юзеры, транзакции  │
│  /app/web/payhooks.py  — вебхуки провайдеров + демо    │
├────────────────────────────────────────────────────────┤
│  /app/payments.py — CryptoBot, xRocket, ЮMoney         │
│  /app/auth.py     — сессии, PBKDF2, CSRF, флеш         │
│  /app/db.py       — SQLite (деньги в копейках, int)    │
├────────────────────────────────────────────────────────┤
│  SQLite (WAL) → этап 6: PostgreSQL + Redis             │
└────────────────────────────────────────────────────────┘
```

**Принципы:**
- Деньги — только целые копейки (`INT`), форматирование на выводе.
- Любое движение денег = запись в `transactions` (журнал аудита).
- Зачисления депозитов идемпотентны (повторный вебхук не начислит дважды).
- CSRF-токен во всех POST-формах; сессии — httponly-cookie, 30 дней.
- Провайдер без настроенных ключей автоматически работает в демо-режиме.

## 4. Модель данных

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `users` | аккаунты (владелец и рекламодатель в одном) | email, pass_hash (PBKDF2), balance_kop, is_admin, banned |
| `sessions` | сессии | token, user_id, expires_at |
| `listings` | площадки | platform(tg/vk), kind(channel/chat/bot), link, category_id, subscribers, err, price_24h…price_native (копейки), status, verified, views |
| `categories` | категории каталога | slug, name, emoji |
| `orders` | заказы на размещение | listing_id, buyer_id, fmt, price_kop, commission_kop, comment, contact, status |
| `transactions` | журнал денег | user_id, kind(deposit/order_hold/order_refund/order_payout/admin_adjust), amount_kop, status, provider, external_id |
| `reviews` | отзывы (только после completed-заказа) | listing_id, order_id, rating 1–5, text |

**Статусы заказа:** `new → accepted → published → completed` (+ `declined/cancelled` — авто-возврат, `disputed` — арбитраж, `refunded`).

## 6. Платёжные интеграции — практические детали

### 6.1 CryptoBot (`@CryptoBot`)
- **Получить:** @CryptoBot → Crypto Pay → Create App → токен.
- **API:** `https://pay.crypt.bot/api` (testnet: `testnet-pay.crypt.bot`).
- **Инвойс:** `createInvoice` (asset=USDT, amount по курсу, payload=`deposit:<tx_id>`).
- **Подтверждение:** вебхук `invoice_paid` → обязательная перепроверка
  `getInvoices` (тело вебхука не подписано) → идемпотентное зачисление.
- **Переменные:** `CRYPTOBOT_TOKEN`, `CRYPTOBOT_TESTNET`.

### 6.2 xRocket Pay
- **Получить:** приложение xRocket → API-токен в настройках Pay.
- **API:** `https://pay.xrocket.eu/api` (`X-Rocket-Pay-Token`).
- **Инвойс:** `createInvoice` (currencyType=crypto, currency=USDT, webhookUrl).
- **Подтверждение:** вебхук со статусом paid/success → зачисление.
- **Переменные:** `XROCKET_TOKEN`, `XROCKET_API_URL`.

### 6.3 ЮMoney
- **Получить:** кошелёк ЮMoney → Настройки → «HTTP-уведомления»:
  URL `{BASE_URL}/pay/yoomoney/notify` + секрет уведомлений.
- **Оплата:** quickpay-ссылка (`receiver`, `paymentType=AC` карта / `PC` кошелёк,
  `label=rupor-deposit-<tx_id>`, `sum`).
- **Подтверждение:** POST-уведомление; проверка `sha1_hash`
  (secret & operation_id & amount & currency & datetime & sender & codepro & label).
- **Переменные:** `YOOMONEY_PURSE`, `YOOMONEY_SECRET`.
- ⚠️ Для регулярных приёмов от юрлица — «ЮKassa» (отдельная интеграция, этап 5).

### Общие правила денег
1. Депозит создаётся как `pending`-транзакция; зачисление — только после
   подтверждения провайдером (вебхук / проверка / админ).
2. Эскроу: при брони сумма уходит с баланса покупателя «в никуда» (журнал
   `order_hold`); при отказе — `order_refund`; при завершении владельцу —
   `order_payout` = цена − комиссия.
3. Комиссия платформы = `COMMISSION_PCT` (по умолчанию 10%) с завершённых заказов.

## 7. Безопасность (что уже сделано + что впереди)

**Сделано:** PBKDF2-пароли (200k итераций), httponly-сессии, CSRF на всех
POST, параметризованный SQL (без инъекций), идемпотентные зачисления,
перепроверка вебхуков запросом к API, деньги в int-копейках.

**Впереди (этап 1–5):** rate-limiting, 2FA админов, аудит-лог действий
админов, анти-фрод, шифрование чувствительных полей, WAF/Cloudflare.

## 8. Чек-лист продакшен-запуска

- [ ] Домен + HTTPS (например, `rupor.su` / `rupor-ads.ru`).
- [ ] Прод-секреты в env: `SECRET_KEY`, токены трёх провайдеров.
- [ ] `BASE_URL` = публичный домен (влияет на вебхуки и ссылки оплаты).
- [ ] Настроить вебхуки у всех провайдеров.
- [ ] Первый аккаунт = админ (или `ADMIN_EMAILS`).
- [ ] Юр. документы: оферта, политика, правила (черновики в `documents/`).
- [ ] Бэкапы БД, мониторинг, алерты платежей.
- [ ] Стартовый наполнение: 30–50 площадок вручную/партнёрами.
